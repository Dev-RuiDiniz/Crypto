# Auditoria Tecnica do Repositorio (2026-03-01)

## Escopo
- Revisao tecnica do backend, API, seguranca e fluxo de execucao local.
- Execucao de testes automatizados (`pytest`) em Windows.
- Verificacao de dependencias (`pip check`, `pip-audit`).
- Validacao de boot local com `app.launcher`.

## Ambiente de validacao
- SO: Windows (PowerShell).
- Python: 3.12.3.
- Node: v22.11.0.
- NPM: 10.9.0.
- Venv usado na auditoria: `.venv-win312`.

## Resultado objetivo
- `pytest -q`: `39 passed`, `16 failed`, `2 errors`.
- `pip check`: sem conflitos de dependencias.
- `pip-audit`: 13 vulnerabilidades conhecidas em 3 pacotes.

## Achados

### Critico
1. Segredos expostos em arquivo versionado.
- Evidencia: `config.txt:95`, `config.txt:96`, `config.txt:103`, `config.txt:104`, `config.txt:111`, `config.txt:112`.
- Impacto: risco de comprometimento de conta/exchange.
- Acao recomendada:
  - Rotacionar chaves imediatamente.
  - Remover valores reais de `config.txt`.
  - Usar apenas cofre (`exchange_credentials`) e variaveis de ambiente.

### Alto
2. API sobrescreve `Content-Type` de toda resposta para JavaScript.
- Evidencia: `api/server.py:168`, `api/server.py:175`, `api/server.py:176`.
- Impacto: respostas JSON passam com `Content-Type` incorreto; `FlaskClient.get_json()` retorna `None`; quebra de contratos HTTP e testes.
- Acao recomendada:
  - Remover override global no `@app.after_request`.
  - Aplicar ajuste de mime apenas para assets `.js/.mjs`.

3. Worker falha com `config.txt` padrao por ausencia de credenciais no cofre.
- Evidencia: `bot.py:345`, `bot.py:347`, `bot.py:348`.
- Impacto: launcher sobe API, mas worker encerra no boot.
- Acao recomendada:
  - Ajustar onboarding para exigir cadastro em `exchange_credentials`.
  - Oferecer modo dev sem exchanges habilitadas (foi adicionado `config.windows.local.txt`).

### Medio
4. Caracteres nao-ASCII em logs causam erro em console cp1252.
- Evidencia: `api/server.py:329` e varios `print/ulog` com `❌` em `bot.py` (ex.: `bot.py:329`, `bot.py:530`).
- Impacto: ruído operacional e stack traces de logging em Windows sem UTF-8.
- Acao recomendada:
  - Trocar emojis por ASCII em logs de runtime, ou forcar UTF-8.

5. Locks de SQLite em Windows durante testes.
- Evidencia: falhas `PermissionError [WinError 32]` em `tests/test_sprint5_idempotency.py`, `tests/test_paper_multipair.py`, `tests/test_sprint7_arbitrage.py`, `tests/test_config_version.py`.
- Contexto: `StateStore` abre conexao persistente (`core/state_store.py:38`) e o `close()` (`core/state_store.py:1387`) nao e sempre chamado nos testes.
- Impacto: limpeza de diretories temporarios falha no teardown no Windows.
- Acao recomendada:
  - Fechar `StateStore` explicitamente em `tearDown`.
  - Considerar contexto gerenciado para lifecycle do store.

### Baixo
6. Arquivo de script manual sendo coletado como teste automatizado.
- Evidencia: `test_server.py:5` (`test_endpoint(endpoint)` sem fixture).
- Impacto: erro de coleta em `pytest`.
- Acao recomendada:
  - Renomear para `scripts/test_server_manual.py` ou proteger com `if __name__ == "__main__":`.

7. Uso recorrente de `datetime.utcnow()` (deprecado em Python 3.12+).
- Evidencia: `api/server.py:163`, `api/server.py:188`, `api/server.py:198`, varios pontos em `core/state_store.py`.
- Impacto: warnings e manutencao futura.
- Acao recomendada:
  - Migrar para `datetime.now(datetime.UTC)`.

## Dependencias com vulnerabilidade (pip-audit)
- `aiohttp==3.10.8`: CVE-2024-52304, CVE-2024-52303, CVE-2025-53643 e CVEs adicionais 2025; fixes em linhas 3.10.11/3.12.14/3.13.3.
- `cryptography==44.0.1`: CVE-2026-26007 (fix 46.0.5).
- `flask==3.0.3`: CVE-2026-27205 (fix 3.1.3).

## Validacao de inicializacao local
- API validada com sucesso em `http://127.0.0.1:8000/api/health`.
- Worker validado com sucesso em `http://127.0.0.1:8000/api/health/worker`.
- Validacao feita com `config.windows.local.txt` (modo PAPER e exchanges desabilitadas).

## Prioridade de correcao sugerida
1. Rotacionar segredos e limpar `config.txt`.
2. Corrigir `Content-Type` global da API.
3. Atualizar dependencias vulneraveis.
4. Ajustar lifecycle de conexao SQLite para estabilidade no Windows.
5. Corrigir encoding de logs e warnings de `datetime`.
